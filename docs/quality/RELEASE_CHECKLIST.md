# Checklist de livraison

## Produit et métier

- [ ] Périmètre et critères d’acceptation confirmés.
- [ ] Parcours métier revus avec les rôles concernés.
- [ ] Contenus cliniques et IA soumis à validation humaine explicite.
- [ ] Accessibilité et usage mobile vérifiés si applicables.

## Données et sécurité

- [ ] Autorisations serveur et isolation inter-organisations testées.
- [ ] Aucun secret ou donnée réelle dans le diff, les logs et les artefacts.
- [ ] Flux, sous-traitants et rétention mis à jour.
- [ ] Sauvegarde, restauration et retour arrière évalués.
- [ ] Constats critiques ou hauts corrigés, vérifiés ou formellement acceptés.

## Technique

- [ ] Tests, analyse statique et build pertinents réussis.
- [ ] Migrations examinées sur données synthétiques représentatives.
- [ ] Compatibilité et erreurs d’intégration vérifiées.
- [ ] Observabilité suffisante sans contenu sensible.

## GitHub et Vercel

- [ ] Branche, diff et cible de fusion vérifiés.
- [ ] Workflow GitHub réussi.
- [ ] Variables Vercel vérifiées par environnement sans exposer leur valeur.
- [ ] Preview contrôlée.
- [ ] Cible de production et autorisation confirmées.
- [ ] Procédure de retour arrière prête.
